# OpenWrt на Xiaomi BE5000 (Airoha AN7563)

[English](README.md) · **Русский**

> [!IMPORTANT]
> **Коротко.** Репозиторий описывает, как поставить OpenWrt на Xiaomi BE5000, имея только root-доступ по SSH, и как поднять роутер по UART, если загрузчик сломался.
> - **Три шага:** одна команда на компьютере, один файл через браузер, настройка Wi-Fi. Установщик сначала проверяет чип флеша: загрузчик здесь знает 57 чипов NAND, включая **Winbond W25N01KV**, на котором загрузчики xinyooo и X-WRT падают (`PANIC at PC : 0x810017a9`).
> - **Скорость Wi-Fi:** 1897 Мбит/с скачивание и 1778 Мбит/с отдача через BE5000 (OpenSpeedTest, MacBook 2x2 на 160 МГц до ПК в проводной сети).
> - **Два образа:** обычный и с VPN (AmneziaWG 3.1, Xray из форка Amnezia, zapret, DNS по HTTPS, маршрутизация по правилам — всё с LuCI). Через VPN на самом роутере, быстрее с выключенным NPU: AmneziaWG 251 Мбит/с скачивание и 236 Мбит/с отдача (212 и 178 с NPU), Xray (VLESS + Reality + xhttp) 137 и 117 Мбит/с (121 и 119).
> - **Проверено на железе:** BE5000 (AN7563PT, W25N01KV, 512 МБ DDR3): установка из стоковой прошивки Xiaomi по SSH, восстановление по UART, установка через веб-failsafe, холодный старт, своя сборка OpenWrt с настройками в UBI, калибровка Wi-Fi из заводских данных Factory самого роутера.

## 1. Что работает

Всё ниже проверено на BE5000 с этой прошивкой.

| Что | Как работает |
|---|---|
| **Система** | OpenWrt SNAPSHOT `r36539+1067`, ядро **Linux 6.18.55** ([подробности сборки](firmware/openwrt/README.md), англ.) |
| **Wi-Fi 5 ГГц** | 3x3, 160 МГц, Wi-Fi 6/7. MacBook 2x2 (2 потока, канал 2402 Мбит/с): скачивание **1897 Мбит/с**, отдача **1778 Мбит/с** ([замер](docs/en/technical.md#speed), англ.) |
| **Wi-Fi 7** | WPA3 с GCMP-256 и MLO (2,4 + 5 ГГц) тоже идут через NPU: клиент Wi-Fi 7 на WPA3 отдаёт 1560–1760 Мбит/с |
| **Wi-Fi 2,4 ГГц** | 2x2, работает, 20/40 МГц |
| **Аппаратное ускорение** | трафик Wi-Fi ↔ провод идёт через PPE и NPU, процессор на полной скорости загружен на ~10%. NPU выключается в LuCI, если нужен быстрый VPN ([подробнее](#ускорение-npu-и-vpn)) |
| **VPN** (образ с VPN) | AmneziaWG 3.1, Xray из форка Amnezia (VLESS, Reality, xhttp), zapret, https-dns-proxy, pbr; всё с LuCI и русским переводом ([подробнее](#два-образа)) |
| **Роуминг** | 802.11r: телефоны и ноутбуки бесшовно переходят между BE5000 и другой точкой OpenWrt с той же сетью |
| **Порты** | WAN 2,5 Гбит/с (DHCP-клиент) и три LAN по 1 Гбит/с |
| **Настройки** | сохраняются после перезагрузок и отключения питания, переносятся при обновлении прошивки; в `/overlay` около 79 МБ свободно под настройки и пакеты |
| **Температура** | датчики SoC в `/sys/class/thermal` (63–69 °C); при 105 °C частота процессора снижается |
| **Перезагрузка** | обычная и по питанию, без зависаний; при зависании роутер сам перезагружается через ~30 с (watchdog). Исключение — перезагрузка сразу после `sysupgrade` ([известные проблемы](#известные-проблемы)) |
| **Управление** | веб-интерфейс LuCI и SSH на `192.168.1.1`, обновления через `sysupgrade`. LuCI на английском, русском, украинском, китайском, немецком, испанском, французском и португальском (Бразилия): язык выбирается по браузеру или в **System → System → Language and Style**. В диалоге каждого радио только его диапазон (исправление iwinfo для MT7992, где оба радио — одно устройство) |
| **Пакеты** | `apk add` из источников OpenWrt; модули ядра (`kmod-*`, все 1100) и пакеты образа с VPN из [своего источника этой сборки](https://pabragin.github.io/xiaomi-be5000-openwrt/) |
| **MAC-адреса** | с наклейки роутера, из его заводской калибровки |

**Ограничение:** скачивание на одном быстром клиенте упирается примерно в 1,9 Гбит/с. Предел задаёт канал PCIe между процессором и радио (одна линия, 5 GT/s).

### Два образа

В каждом релизе два образа. Оба ставятся одинаково, между ними можно переходить обычным `sysupgrade` с сохранением настроек.

| Файл в релизе | Что внутри |
|---|---|
| `openwrt-airoha-an7563-xiaomi_be5000-squashfs-sysupgrade.bin` | обычный: Wi-Fi, ускорение NPU, LuCI |
| `openwrt-airoha-an7563-xiaomi_be5000-full-squashfs-sysupgrade.bin` | с VPN: то же плюс AmneziaWG 3.1, Xray из форка Amnezia, zapret, https-dns-proxy (DNS по HTTPS) и pbr (маршрутизация по правилам), все с LuCI |

- **В образе с VPN всё выключено.** Пакеты стоят, но службы не запущены: их включают и настраивают в LuCI. DNS по HTTPS тоже выключен, потому что после включения он забирает себе DNS всей сети.
- **В обычный образ** те же пакеты ставятся через `apk add` из [источника этой сборки](https://pabragin.github.io/xiaomi-be5000-openwrt/).
- **Там же, только через `apk add`:** `luci-app-podkop` (с `luci-i18n-podkop-ru`; подтянет sing-box), `luci-app-nikki` (mihomo), `youtubeUnblock` + `luci-app-youtubeUnblock`, `byedpi`. В образы они не входят: sing-box и mihomo занимают по 10–19 МБ. Ставятся в `/overlay` (~79 МБ). Как и везде в OpenWrt, `sysupgrade` переносит настройки, но не доставленные пакеты: после обновления их ставят заново, настройки подхватятся. В образе с VPN пакеты уже внутри.

### Ускорение NPU и VPN

Переключатель в LuCI: **Сеть → Ускорение NPU**. По умолчанию NPU включён. Изменение перезапускает Wi-Fi на несколько секунд.

| Что | NPU включён | NPU выключен |
|---|---|---|
| Wi-Fi ↔ проводная сеть | до ~1,9 Гбит/с | ~1,1 Гбит/с |
| Трафик самого роутера по Wi-Fi (VPN, zapret, службы) | ~450 Мбит/с | до ~900 Мбит/с |
| AmneziaWG на роутере | 212 / 178 Мбит/с | 251 / 236 Мбит/с |
| Xray на роутере (VLESS + Reality + xhttp) | 121 / 119 Мбит/с | 137 / 117 Мбит/с |

| NPU включён: Wi-Fi ↔ провод | NPU выключен: через AmneziaWG на роутере |
|---|---|
| <img src="images/openspeedtest-be5000-npu-on.png" alt="OpenSpeedTest через BE5000 с NPU: 1897 Мбит/с скачивание, 1778 Мбит/с отдача" width="320"> | <img src="images/openspeedtest-be5000-amneziawg.png" alt="OpenSpeedTest через AmneziaWG на BE5000 без NPU: 251 Мбит/с скачивание, 236 Мбит/с отдача" width="320"> |

Все замеры: OpenSpeedTest с MacBook 2x2 на 160 МГц до ПК в проводной сети. Справа MacBook подключён через туннель AmneziaWG к серверу на самом BE5000. Цифры VPN в таблице сняты так же, Xray — через VLESS + Reality + xhttp к серверу на BE5000.

- **Когда выключать NPU:** только ради максимальной скорости VPN на самом роутере: без NPU AmneziaWG даёт 251/236 Мбит/с против 212/178 с NPU, Xray — 137/117 против 121/119, зато Wi-Fi ↔ провод падает с ~1,9 до ~1,1 Гбит/с. В остальных случаях NPU лучше оставить.
- **Трафик самого роутера с NPU:** кадры, адресованные роутеру, NPU копирует в память Linux, читая их через кэшируемую область памяти. Это даёт ~450 Мбит/с, поэтому VPN на роутере упирается в процессор, а не в NPU.
- **Потолок без NPU** задаёт процессор: два ядра Cortex-A53 в 32-битном режиме без NEON, поэтому шифрование идёт только скалярным кодом. Под AmneziaWG процессор занят полностью.
- **Xray медленнее AmneziaWG:** он шифрует в пространстве пользователя кодом на Go, а AmneziaWG — в ядре. Аппаратного AES у процессора нет, и AES-GCM в Go дал бы около 35–45 Мбит/с. Поэтому Xray в образе предлагает ChaCha20-Poly1305 первым, если у процессора нет AES-инструкций, как это делает Chrome на таких процессорах. Так же он работает, когда BE5000 — клиент удалённого сервера Reality: скачивание ~125–135 Мбит/с.

### Известные проблемы

- **Перезагрузка после `sysupgrade`** иногда зависает: на этой сборке примерно 1 раз из 3. Индикатор не горит, сам роутер не перезагружается. Выньте питание и включите снова: прошивка и настройки к этому моменту уже записаны (проверено по логу через netconsole). Обычные перезагрузки, в том числе по питанию, не зависают. Зависание происходит после программного сброса процессора, когда watchdog ещё не работает. Причина ищется.

## 2. Что нужно

- **Роутер с root-доступом по SSH** на стоковой прошивке Xiaomi. Как получить root на стоке, здесь не описано: используйте [xmir-patcher](https://github.com/openwrt-xiaomi/xmir-patcher), он знает BE5000; помощь — в [теме на 4PDA](https://4pda.to/forum/index.php?showtopic=1088946). Уже стоит OpenWrt xinyooo/iscle? Нужен только [`sysupgrade -n`](#с-openwrt-xinyooo-или-iscle).
- **Компьютер** с macOS, Linux или Windows (на Windows нужен [Git for Windows](https://git-scm.com/download/win) с Git Bash или WSL): `ssh`, `curl` и `git` (или скачайте репозиторий как ZIP через зелёную кнопку **Code**), и **сетевой кабель** до роутера. `python3` нужен только для восстановления по UART и скрипта проверки загрузчика.

## 3. Установка

> [!WARNING]
> Установка перезаписывает заводские разделы `bdata` и `Factory`. Вернуться на прошивку Xiaomi можно только из полного бэкапа, который установщик снимет на шаге 1.

**Шаг 1. Одна команда на компьютере.** Подключите компьютер кабелем к порту LAN роутера (не к порту 2.5G). Скачайте репозиторий и запустите установщик с адресом роутера:

```sh
git clone https://github.com/pabragin/xiaomi-be5000-openwrt && cd xiaomi-be5000-openwrt
sh install.sh root@192.168.31.1        # 192.168.31.1 — адрес стока Xiaomi; на OpenWrt обычно 192.168.1.1
```

На Windows в командной строке из папки репозитория: `install.bat root@192.168.31.1` (или двойной щелчок по `install.bat`, тогда адрес по умолчанию `192.168.31.1`). Он запускает тот же `install.sh` через Git Bash, а без него — через WSL. Установка проверена на Windows 8.1 с Git for Windows.

Сам скрипт пишет только калибровку и загрузчик, а прошивку OpenWrt вы потом загружаете через браузер (шаг 2). Чтобы файл был под рукой и без интернета, скрипт сразу скачивает из [последнего релиза](https://github.com/pabragin/xiaomi-be5000-openwrt/releases/latest) оба образа — обычный и `full` с VPN — и сверяет их с контрольными суммами релиза. Нужен только один — передайте его вторым аргументом: `sh install.sh root@192.168.31.1 full` (или `plain`).

Если образ не скачивается или он у вас уже есть — см. [«Если образ не скачивается»](#если-образ-не-скачивается).

Потом скрипт один раз спросит пароль роутера и:
1. проверит чип флеша и разделы (если загрузчик не поддерживает чип, остановится, ничего не записав);
2. сохранит полный бэкап флеша в папку `be5000-backup-<дата>` (её нужно сохранить: без неё прошивку Xiaomi не вернуть);
3. спросит `YES`, перенесёт калибровку Wi-Fi и запишет загрузчик;
4. перезагрузит роутер.

**Шаг 2. Прошивка через браузер.**
1. Задайте компьютеру адрес вручную: IP `192.168.1.10`, маска `255.255.255.0`. На macOS: «Настройки → Сеть → (адаптер) → Подробнее → TCP/IP → Вручную». В WSL адрес задаётся в Windows, а файл в браузере лежит в `\\wsl$\<дистрибутив>\home\…`.
2. Откройте `http://192.168.1.1` в современном браузере (Internet Explorer и старые версии Chromium не показывают загрузку образа и не открывают LuCI), выберите один из образов с шага 1 — обычный или `full` (установщик в конце печатает пути к ним), нажмите **Upload**, затем **Proceed**.
3. Подождите 5 минут и не выключайте питание. Роутер сам перезагрузится в OpenWrt.

**Шаг 3. Настройка.** Верните компьютеру автоматический адрес (DHCP), откройте `http://192.168.1.1` и задайте пароль. Затем в **Network → Wireless** укажите страну, имя и пароль сети и нажмите **Enable** у обоих радио (Wi-Fi по умолчанию выключен). Порт 2.5G — это WAN, адрес от провайдера он получает по DHCP; три порта 1G — LAN. Чтобы использовать роутер как точку доступа за другим роутером, удалите интерфейсы `wan` и `wan6` в **Network → Interfaces**, затем добавьте `eth1` в **Devices → br-lan → Bridge ports**. Нельзя держать `eth1` одновременно в мосту и в `wan`: локальная сеть сольётся с сетью вышестоящего роутера, и `192.168.1.1` станет недоступен. WAN и LAN получают заводские MAC-адреса из стокового окружения U-Boot, которое лежит в первом блоке `art`.

> [!CAUTION]
> Если во время записи загрузчика пропало питание или после шага 1 роутер не появляется в сети, поднять его можно только по UART (раздел 4).

**Назад на Xiaomi.** Только из бэкапа шага 1, и эта процедура здесь не проверялась. Заводские разделы не совпадают с разделами OpenWrt, поэтому их пишут по абсолютным смещениям из консоли U-Boot через UART (`python3 scripts/pc/be5000-uart-recover.py ПОРТ --console`, команды `mtd` описаны в [инструкции по UART](docs/ru/recovery-uart.md#калибровка-из-консоли-u-boot)): для каждого файла `mtdN-<имя>.bin` из бэкапа `tftpboot 0x84000000 mtdN-<имя>.bin`, `mtd erase spi-nand0 СМЕЩЕНИЕ РАЗМЕР`, `mtd write spi-nand0 0x84000000 СМЕЩЕНИЕ РАЗМЕР`, где смещение и размер берутся из `sysfs_mtd.txt` бэкапа; загрузчик (`mtd0`, смещение 0) последним. Загрузчик можно записать и скриптом восстановления: `python3 scripts/pc/be5000-uart-recover.py ПОРТ --image be5000-backup-<дата>/mtd0-<имя>.bin`.

Каждый шаг по отдельности, ручная проверка чипа и случай `READ-ONLY`: [docs/ru/install-ssh.md](docs/ru/install-ssh.md).

### Если образ не скачивается

`install.sh` может не скачать образ, если GitHub недоступен или обрывает загрузку. Тогда скачайте файлы вручную, и скрипт возьмёт их с диска:

1. Откройте [страницу последнего релиза](https://github.com/pabragin/xiaomi-be5000-openwrt/releases/latest) и скачайте:
   - образ: `openwrt-airoha-an7563-xiaomi_be5000-squashfs-sysupgrade.bin` (обычный) или `openwrt-airoha-an7563-xiaomi_be5000-full-squashfs-sysupgrade.bin` (`full`, с VPN);
   - `SHA256SUMS` — по нему скрипт проверит, что файл скачался целиком.
2. Положите оба файла в папку `firmware/openwrt/` внутри репозитория (папки нет — создайте):
   ```
   xiaomi-be5000-openwrt/
   └── firmware/
       └── openwrt/
           ├── openwrt-airoha-an7563-xiaomi_be5000-squashfs-sysupgrade.bin
           └── SHA256SUMS
   ```
   Имя должно быть ровно `SHA256SUMS`, без расширения: если браузер сохранил его как `SHA256SUMS.txt`, переименуйте. Если образ лежит в другом месте и вы указываете его через `BE5000_IMAGE`, `SHA256SUMS` можно положить рядом с образом.
3. Запустите установщик как обычно: `sh install.sh root@192.168.31.1` (на Windows — `install.bat root@192.168.31.1`).
4. Скрипт напишет `checksum OK` и пойдёт дальше, ничего не скачивая.

| Ситуация | Что сделает `install.sh` |
|---|---|
| Образ и `SHA256SUMS` в `firmware/openwrt/` | сверит контрольную сумму и возьмёт образ |
| Только образ, без `SHA256SUMS` | проверит, что образ для BE5000, предупредит `checksum NOT checked` и возьмёт его |
| Нужен только один образ | передайте вторым аргументом `plain` или `full`, второй скачиваться не будет |
| Образ лежит в другом месте | укажите путь: `BE5000_IMAGE=/путь/к/образу.bin sh install.sh root@192.168.31.1` |
| Образ из старого релиза, а интернет есть | скачает образ из последнего релиза |
| Контрольная сумма не сошлась | остановится: файл повреждён или из другого релиза — скачайте заново |

### С OpenWrt xinyooo или iscle

Ваш загрузчик уже грузит ваш чип флеша, а калибровка уже лежит в `0xA0000`, поэтому `install.sh` не нужен (и не смог бы записать загрузчик: на тех образах `u-boot` только для чтения). На компьютере:

```sh
curl -LO https://github.com/pabragin/xiaomi-be5000-openwrt/releases/latest/download/openwrt-airoha-an7563-xiaomi_be5000-squashfs-sysupgrade.bin
ssh root@192.168.1.1 'cat > /tmp/sysupgrade.bin' < openwrt-airoha-an7563-xiaomi_be5000-squashfs-sysupgrade.bin
ssh root@192.168.1.1 sysupgrade -n /tmp/sysupgrade.bin
```

После перезагрузки роутер на `192.168.1.1`, root без пароля, Wi-Fi выключен: дальше шаг 3. Этот путь здесь ещё не проверялся. Настройки не сохраняются: этот образ хранит их в UBI, а не в JFFS2, потому что на флеше W25N01KV JFFS2 портит записи и роутер после перезагрузки поднимается без сети ([issue #1](https://github.com/pabragin/xiaomi-be5000-openwrt/issues/1)).

### С прошлого релиза этой сборки

```sh
curl -LO https://github.com/pabragin/xiaomi-be5000-openwrt/releases/latest/download/openwrt-airoha-an7563-xiaomi_be5000-squashfs-sysupgrade.bin
ssh root@192.168.1.1 'cat > /tmp/sysupgrade.bin' < openwrt-airoha-an7563-xiaomi_be5000-squashfs-sysupgrade.bin
ssh root@192.168.1.1 sysupgrade /tmp/sysupgrade.bin
```

Для образа с VPN — те же команды с файлом `openwrt-airoha-an7563-xiaomi_be5000-full-squashfs-sysupgrade.bin`. Настройки сохраняются. Если после перезагрузки индикатор не загорается, см. [известные проблемы](#известные-проблемы).

| Сейчас стоит | Как обновиться |
|---|---|
| be5000-openwrt-20261018 или новее | сразу на последний релиз |
| be5000-openwrt-20261016 или 20261017 | **сначала** [be5000-openwrt-20261018](https://github.com/pabragin/xiaomi-be5000-openwrt/releases/tag/be5000-openwrt-20261018), **потом** последний релиз |
| стоковая прошивка Xiaomi, xinyooo, iscle | сразу на последний релиз: [установка](#3-установка) или [`sysupgrade -n`](#с-openwrt-xinyooo-или-iscle) |

> [!WARNING]
> С 20261016 и 20261017 обновляйтесь только через 20261018. Только он переносит настройки со старого раздела на 40 МБ в новый на 93 МБ. Более новые релизы старую разметку не переносят: они отформатируют раздел настроек, и настройки пропадут.

## 4. Если загрузчик сломался: UART

Признаки: тишина в сети, в UART-логе `PANIC at PC : 0x810017a9` или любая остановка до U-Boot.

![Цепочка загрузки](images/boot-chain.svg)

1. Подключите USB-UART: GND–GND, TX↔RX, **VCC не подключать**, 115200 8N1.
   ![Подключение](images/uart-wiring.svg)
2. Запустите `python3 scripts/pc/be5000-uart-recover.py /dev/ttyUSB0` (на macOS порт называется `/dev/cu.usbserial-…`).
3. Замкните **GPIO0 на GND**, держите и включите питание. Где площадка — на [фото](docs/ru/recovery-uart.md#где-gpio0).
4. Скрипт сам пройдёт оба этапа XMODEM и запишет загрузчик. Затем разомкните GPIO0.

Подробно, с фото и таблицей ошибок: [docs/ru/recovery-uart.md](docs/ru/recovery-uart.md).

## 6. Как это устроено

| Компонент | Что стоит на флеше |
|---|---|
| Загрузчик (0x0–0x80000) | BL2 с поддержкой W25N01KV + BL31 + U-Boot 2026.01 (автозагрузка, веб-failsafe на `192.168.1.1`: если при включении зажат Reset или нечего загружать) |
| Калибровка Wi-Fi | заводская EEPROM MT7992 перенесена в блок `0xA0000` (раздел `art` — так в OpenWrt принято называть раздел с калибровкой Wi-Fi; на стоке она лежит в `Factory`) |
| Прошивка | OpenWrt (своя сборка на основе [iscle](https://github.com/iscle/openwrt)) в разделе `firmware` с `0xC0000`, 24 МБ |
| Настройки | раздел `ubi-data` с `0x18C0000`, 93 МБ, том `rootfs_data` (UBIFS) |

![Разметка флеша](images/flash-layout.svg)

<details>
<summary>Зачем в <code>art</code> первый блок</summary>

Раздел `art` (`0x80000`, 256 КБ) состоит из двух блоков по 128 КБ: калибровка Wi-Fi лежит во втором, в `0xA0000` (смещение `0x20000` внутри раздела).

- **Первый блок — стоковое окружение Xiaomi:** на стоке по этому адресу был раздел `u-boot-env` с заводскими MAC-адресами (`ethaddr`, `ethaddr_wan`), серийным номером, `uart_en`, `telnet_en` и т. п. Установщик блок не стирает. OpenWrt туда не пишет и при первой загрузке читает из него только MAC-адреса для LAN и WAN.
- **Откуда он взялся:** разметка `art` взята из первых сборок OpenWrt для BE5000 (xinyooo и iscle) — там раздел тоже `0x80000`, 256 КБ, с калибровкой в `0xA0000`.
- **Почему его не убрать:** у тех, кто переходит с xinyooo или iscle через `sysupgrade -n`, калибровка уже лежит в `0xA0000`, а прошивка начинается с `0xC0000`. Сдвиг разметки потребовал бы переноса калибровки и нового загрузчика ради 128 КБ.
</details>

<details>
<summary>Почему в <code>/overlay</code> около 79 МБ, а не 93</summary>

Раздел `ubi-data` занимает 93,1 МБ, но часть места уходит на служебные данные UBI и UBIFS (цифры с роутера на W25N01KV без бэд-блоков):

| Этап | Остаётся | Куда ушло |
|---|---|---|
| Раздел `ubi-data` | 93,1 МБ (745 блоков по 128 КБ) | — |
| Заголовки UBI | 90,2 МБ | в каждом блоке 4 КБ (две страницы по 2 КБ) — служебные заголовки, полезно 124 КБ из 128 |
| Резерв UBI | 87,4 МБ (том `rootfs_data`, 722 блока) | 19 блоков на замену будущих бэд-блоков, ещё 4 — таблица томов и переразметка |
| Служебные области UBIFS | 86 МБ (711 блоков) | индекс, таблицы свободного места, лог |
| Журнал UBIFS | ≈79 МБ — это `df` для `/overlay` | 4 МБ под журнал записи |
| Резерв для root | 74,6 МБ в колонке «Available» | 4 МБ UBIFS держит про запас для root; на OpenWrt всё работает от root, так что на деле доступны почти все 79 МБ |

- **Резерв на бэд-блоки и журнал** защищают флешку от износа и настройки от порчи при внезапном отключении питания. Урезать их не стоит: выигрыш 2–3 МБ.
- **Реально помещается больше:** UBIFS сжимает файлы на лету, текстовые конфиги и скрипты занимают в 2–3 раза меньше своего размера.
- **На чипе с заводскими бэд-блоками** места немного меньше: каждый бэд-блок минус 128 КБ.
</details>

- **Что внутри загрузчика.** BL2 со списком из 57 чипов NAND (включая W25N01KV), BL31 и U-Boot 2026.01 xinyooo с автозагрузкой и веб-failsafe.
- **Почему два файла для UART.** BootROM принимает по XMODEM не больше `0x1F800` байт и только FIP с одним BL2. Затем BL2 сам просит `Press x to update firmware` и принимает весь 512 КБ образ, который записывает во флеш.

Подробно, с логами и адресами: [docs/en/technical.md](docs/en/technical.md) (англ.).
